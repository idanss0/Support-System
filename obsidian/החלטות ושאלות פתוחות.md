# החלטות ושאלות פתוחות

> חלק מ-[[מערכת מעקב תמיכה טכנית]]. סיכום של מה שהוחלט עד 2026-10-20.

## החלטות

| נושא | ההחלטה |
|---|---|
| פלטפורמה | Spotfire Cloud, בגרסה האחרונה. לא מפתחים מאפס |
| מי בונה | יועץ Spotfire חיצוני (נבחר). IT מתחזק אחרי העלייה לאוויר |
| פיתוח פנימי | ירד מהפרק (2026-10-19) |
| היקף ה-MVP | מסך חי לראשי הצוותים: P1 פתוחים, SLA בסיכון, בקשות לא משויכות, וקישור לרשומה ב-Salesforce |
| שכבת נתונים | views ב-DW על רשומות פתוחות של Case, CaseMilestone ו-Request, ועוד שמות מ-User, Group ו-Account |
| עדכניות | ה-DW מתעדכן בזמן אמת. היעד: עד 60 שניות מ-Salesforce למסך, ברענון אוטומטי |
| מחוץ ל-MVP | התראת P1 (אוטומציה ב-Salesforce), עומס משוקלל לסוכן, דירוג בתי חולים, גרסאות ו-R&D, RingCentral, דוחות PDF ויעדים |
| טלפון | שלושה עמודי טלפון של המסך החי באפליקציית Spotfire. אפליקציה ייעודית ירדה מהפרק |
| היסטוריה | היסטוריית השדות נשמרת ב-DB, בטבלת Audit trail |
| קהל | 7 ראשי צוותים (3 בטיר 1, 2 בטיר 2, 2 בטיר 3), מנהל התמיכה, ומסך קיר אחד |
| תיעוד | המקור של הפתקים הוא ה-repo. Hook של Claude Code במחשב מעתיק אותם לכספת הזו אחרי כל תשובה. עורכים ב-repo, לא כאן |

## עובדות שנאספו

- כ-100 שיחות נכנסות ביום, כ-50 מיילים ביום, וכ-10,000 קייסים בחודש מכל הסוגים.
- כל פעולה של טיר 1 היא קייס. הסוג נקבע בשדה Case Type.
- אסקלציה היא Request בתוך הקייס, והיא יורשת את ה-Priority וה-SLA מהקייס. Request לטיר 4 יוצר Work Item ב-TFS.
- באג מסומן בשדה ב-Request של טיר 3, ורק אחרי שטיר 4 (R&D) אישר.
- הטלפוניה עברה מ-Avaya Cloud Office ל-RingCentral.
- ה-DW משותף ל-BI, ל-Sales ול-Finance, ו-Spotfire Cloud כבר מחובר אליו.
- קייס שיש בו חשש לפגיעה בחולה מסומן ב-Salesforce ומועבר ל-QARA.
